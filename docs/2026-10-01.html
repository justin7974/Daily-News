Why Dwarkesh is Wrong about Computer Use + How OpenAI shipped its Jev competitor in 1 Week
Computer Use 的进步来自故障恢复和执行方式改变，而不只是更快地点击屏幕。OpenAI 的 Ari Weinstein 介绍，Agent 会结合截图、无障碍信息、DOM 和生成的代码批量操作，并称自己原需两小时的订餐任务由 Agent 十五分钟完成。团队表示，Sol 在 Computer Use 上的任务成本约为 Astra 的七分之一，开发者现可通过 Agents API 使用同一套执行能力。API 团队还介绍了快速决策、异步工具调用和缓存优化；这些是厂商访谈中的能力与案例，不能等同于跨场景独立测试。
🦐点评：Ari 提到模型在自家 harness 上训练，这会让执行层的速度和准确率也成为平台优势。独立 Computer Use 公司如果只包装通用点击能力，既要承担适配成本，又可能落在模型熟悉的执行分布之外；更有价值的资产是特定业务里的成功轨迹、失败恢复和交付责任。
www.latent.space
Early Optimism Reigns on Agentic Commerce + Personal Agents at the Machine Earning AI Summit
常驻个人 Agent 今天每天约花十美元运行，Sapiom 创始人 Ilan Zerbib 认为，成本还需大幅下降才能规模化。Newcomer 的峰会报道同时给出商业应用案例：Gusto CFO 称预测工作由十四天缩至七天，Browserbase 称已有客户让 Agent 完成三十万美元的信用卡采购。OnePay 用独立支出额度限制 Agent，Browserbase 则建设允许浏览、禁止购买的策略引擎。a16z 的 Anish Acharya 判断，通用助手会调用行业专用 Agent；与会者对真实支付授权、用户接受度和责任归属仍有明显分歧。
🦐点评：Browserbase 的大额采购案例比订餐演示更接近可收费的企业需求，但交易额本身并不证明产品收入。OnePay 的支出额度提示了一个切入口：谁能把身份、授权、审计和纠纷处理嵌进交易，谁就可能按业务结果收费；垂直 Agent 的壁垒要看它能否承担具体责任，而非仅能调用银行接口。
www.newcomer.co
Open TTS Leaderboard: Scalable Evaluation for Multilingual Text-to-Speech and Voice Cloning
Hugging Face 上已有八千多个 TTS 模型，但评测没有跟上，Artificial Analysis 的九十二个模型中仅十六个开放权重。新 Open TTS Leaderboard 用识别错误率、说话人相似度和速度等客观指标，将评测周期从数周缩短至数小时。它支持多语言、声音克隆以及 GPU、CPU 首段音频延迟比较，英文表现不能直接代表其他语言。作者明确说明，这些指标无法代替人类对自然度、表现力和听感的判断。
🦐点评：Kokoro、Fish Audio、CosyVoice 等开放模型进入可比较的范围，会削弱只靠英文试听证明溢价的语音 API。评估语音创业公司时，应把目标语种、真实首段延迟和单位交付成本一起测；如果开放模型足够好，客户工作流、专有声音授权与稳定服务才更能支撑毛利。
huggingface.co
OpenAI Dev Day 2026: The releases that actually matter
Claire Vo 用 Astra Ultrafast 实时修改三维游戏世界，一次实验花了约九十七美元：低延迟体验很强，成本仍然显眼。她还用 Decisions API 挑选没人表情尴尬的播客缩略图，测试人机共同绘图，并讨论 Spaces 的协作与 Sites 的内部工具分享。对 Dots，她保留完整评价，承认早期产品仍有粗糙之处。这份实测把发布能力和日常使用感受区分开来，显示速度、权限与费用都在影响产品选择。
🦐点评：九十七美元的游戏实验意味着实时生成应用不能直接沿用传统软件的无限次使用套餐。尽调这类团队，要把一次用户互动拆成推理、生成和缓存成本，再看付费是否覆盖高频修改；能让便宜决策模型承担大部分交互、只在关键步骤调用强模型的产品，才可能扩大使用而不扩大亏损。
www.lennysnewsletter.com
Jev: 8 real use cases for the fastest, cheapest model I’ve ever used | John Lindquist
Jev 的价值在于从给定选项中快速决策，而非像聊天模型一样自由生成内容。John Lindquist 展示实时语音待办、带置信度的数据去重、多级应用路由、Agent 协同和演讲反馈等八类用例。多个决策调用可以串联，用于复杂分类；棋类对比则展示速度、成本和推理能力之间的取舍。节目也讨论它的局限，以及何时仍应使用完整生成模型；可读内容为节目说明和演示目录，未含逐字实录。
🦐点评：数据去重和应用路由说明，低成本决策会把一些原来不值得自动化的微小步骤变成市场。不过 Latent Space 同日访谈已出现 OpenAI 迅速跟进这类接口的信号，Jev 的估值不能只建立在响应速度上；应追问客户是否围绕其决策集、置信度校准和业务反馈形成了难迁移的数据。
www.lennysnewsletter.com

从编程到个人助理：更强大的 AI，更透明的你
ZCode 上传项目数据的风险不只在当前代码，也在完整 Git 历史：报道中的开发者发现约四点二万个文件被打包，超过八成为历史修改记录。智谱承认索引功能曾默认触发上传，随后修复、开源，并宣布删除涉事云端数据、补偿用户。晚点同时梳理 Grok Build 上传、公开分享泄露和提示注入等案例，指出“不用于训练”并不排除日志、安全审查及第三方处理。其对七款产品协议的阅读显示，Agent 权限扩大与用户承担操作后果常常并存；具体条款和事故描述均为报道所述。
🦐点评：ZCode 的索引功能把一次效率提升变成客户代码外流，说明企业采购不会只比较模型分数。能在数据离开客户环境前完成脱敏、限制历史文件读取，并把授权和调用链留成审计证据的基础设施，有机会拿到独立预算；对个人 Agent，掌握更多记忆也意味着更高的事故损失，不能把数据积累全算成护城河。
