How Nvidia Is Trying to Solve the Data Center Power Bottleneck
电力可用性已成为 AI 芯片上线的第一道关口——比拿地、拿芯片更靠前。Nvidia CEO 黄仁勋在高盛科技大会上说，公司正在追踪"全球每一吉瓦的土地、电力和厂房，地球上的一切我们都知道在哪"。文章指出，与 Google、Microsoft、Oracle 合作的数据中心开发商真正担心的，是未来电力短缺导致大批已购芯片闲置。为缓解电力紧张，Nvidia 的视野甚至延伸到 SpaceX 布局涡轮叶片工厂这类供给侧动作。
🦐点评：Nvidia 亲自去数每一吉瓦，等于承认卡住 AI 产能的已不是台积电的产线，而是电网。这把未来 12–18 个月的超额收益从模型层挪到了被忽视的中游——谁能锁定确定性电力（自建电厂、核电 PPA、余热并网），谁就掌握算力的实际定价权；而靠融资囤芯片、却没算清并网时间表的 neocloud，最先暴露的会是折旧和闲置。

Jane Street-Linked Data Center Debt Sours
一笔为 Jane Street 数据中心租约背书的债券，在二级市场迅速走坏——据 FINRA 数据收益率已飙至约 11%，恶化幅度明显大于近期其他 AI 数据中心债券，投资者要求远高于国债的风险补偿才肯持有。Jane Street 过去两年以巨额 AI 支出闻名（大手笔云合同、投资 neocloud CoreWeave），但这次连它背书的项目都没能打动债券买家。
🦐点评：最懂定价的华尔街机构之一背书的数据中心债，都被打到 11% 的收益率——这是 AI 基建叙事里第一道来自债券市场的裂缝。信号很直接："AI 需求无限、租约稳如国债"的估值前提正在被重新定价，靠廉价债务堆 GPU 的 neocloud（CoreWeave 一类）融资成本会先承压。接下来该盯的不是谁签了多大租约，而是租约对手方的信用能不能扛过一轮周期。

System One models like Jev can train their own replacements
"System One"模型（如 Jev）是可被 prompt 驱动的通用快速分类器，能像 LLM 一样处理从邮件分类到玩 Doom 的各类任务，解决了"普通工程团队没能力训练专用分类器"的问题。作者进一步指出它还解决了第二个问题：一旦 Jev 分类器调好，你可以轻松收集它的输入-输出数据，用这些数据训练一个更快更便宜的专用分类器来替代它。换句话说，通用模型先顶上、跑通任务，再蒸馏出专用小模型——通用模型在训练自己的替代者。
🦐点评：这把"先用大模型跑通、再蒸馏成小模型"的链路产品化了：Jev 类模型的真实商业价值不在推理本身，而在它天然产出的、带标注的私有数据流。对投资判断的启发——单靠托管一个通用决策模型很难建壁垒（用户跑通就会蒸馏走），能沉淀"数据飞轮 + 一键蒸馏部署"工具链的公司才握住留存；这也解释了为什么当天 Cognition 的 Kev 等开源自托管方案会一拥而上抢这一层。

Quoting voxium
Simon Willison 收录的一段一线吐槽：入职某大公司半个月，规格、代码、测试、PRD、工单及其解决方案、报告——全部由 Claude Code 生成，团队没人喜欢，却被要求尽可能多地出货。高层反复追问"既然写代码不再是瓶颈，为什么还这么慢？"结果从 L1 到 L7 的所有工程师每天工作 12–13 小时，只是为了"按下回车"，没人真正在读任何东西。
🦐点评："写代码不是瓶颈了，为什么还慢"这句反问，恰恰暴露了 AI 编码工具卖点与组织现实的错位：产能瓶颈已从写代码转移到"读代码、验证、担责"，而这部分没被自动化、反而被放大。对投资人的含义——真正的下一个机会不在生成侧（已拥挤），而在 AI 原生组织的"审阅层"：代码审计、变更验证、责任归属与质量门控，谁能把这层做成基础设施，谁就吃到大厂 all-in Claude Code 之后必然出现的第二波需求。
