Legora 无法查看客户轨迹，用模拟法律任务训练和评估 Agent
Legora 不能读取律师处理客户资料的运行轨迹，因此由三名工程师和三名律师重建业务场景，包括用1 万份文件模拟尽调，并按业务与任务绘制评估结果。CTO Jacob Lauritzen 称，团队另有约一百名法律工程师参与，生产环境则检查十到二十类已知失败。产品从法律检索延伸到 Word 编辑、批量合同审阅与工作协调，Tabular Review 最多支持100 万个单元格，并先跑十行供用户调整。访谈称公司十月以88 亿美元估值融资5.5 亿美元；增长和能力数据均为访谈口径。
🦐点评：Legora 不能看客户原始轨迹，提醒我们别把“客户越多、训练数据自然越多”直接算进估值。真正需要核验的是法律工程师能否把客户问题转成可复用评估，以及新增客户需要多少人工配置；这决定88 亿美元估值背后是软件扩张，还是高人力成本的专业服务。

GPU 算力交易平台融资升温，期货审批与标准化仍未解决
Newcomer 公开正文称，GPU 经纪平台 Ornn 正洽谈新融资，最高一档估值约10 亿美元，Thrive 与 General Catalyst 可能参与；这仍是知情人士口径。Silicon Data 以约一百个来源编制 GPU 租价指数，另有 Architect、Liquid Compute 等布局衍生品。CME 与 ICE 拟推出相关合约，但报道说尚未获批，CME 原定十月五日的启动日已推迟。芯片快速折旧、不同算力能否互换，以及当前短缺是否只是暂时现象，都是交易市场成立前必须回答的问题；付费墙后的内容未获取。
🦐点评：Ornn 靠短期调配算力起家，不能直接套成熟交易所的估值倍数。尽调要先看用户是否愿意在供给宽松时继续交易、同一合约能否交付等效算力；如果这两点不成立，指数和期货只是给一次性的供需错配加了金融包装。

a16z：模型变便宜后，AI 应用要重新证明自己的溢价
a16z 作者认为，客户只需把一个高频任务迁回内部，就足以削弱应用的定价权，无须重建整套产品。文章援引 Harvey 的 Repsol 案例：五十名律师、十二个司法辖区经过八周试点后全面采用，节省时间和采用率来自厂商案例。作者建议按成功完成的工作核算成本，把失败、重试、评估和人工审阅全部计入，并和客户自建方案比较。Clay 的例子则把数据、流程执行与浮动模型成本分开收费，避免简单任务收贵、复杂任务亏钱；这些属于作者主张及其引用案例。
🦐点评：Clay 把流程收费和模型成本分开，提示应用毛利可能来自维护客户工作流程，而非转售 token 的差价。评估高毛利 AI SaaS 时，应把一项核心任务交给客户内部团队复现，再比较含维护和审阅的总成本；只有购买优势仍在，当前溢价才有依据。

Figma 的60 多名 PM 共用 Skills 仓库，增长 Agent 保留一次人工检查
公开节目说明称，Figma PM Ezra Mechaber 与同事把个人 Claude Code 配置整理成 PM OS，包含31 项 Skills，供60 至 70 名 PM 共用。演示覆盖 Slack 信息处理、FigJam 产物生成和 Codex 查错。另一套 AutoXP 负责增长实验，仅保留一次人工检查，节目称首次实验取得明显收益，但公开说明未披露提升幅度。以上来自可读的节目介绍，未获取完整逐字转录，不能据此量化团队生产率。
🦐点评：Figma 用共享仓库让60 多名 PM 复用做法，说明部分非研发需求可以先由内部工具满足。面向 PM 的创业产品若只出售一套提示词，很容易遇到这种替代；更有价值的收费点可能是管理实验权限、记录决策和证明收益，AutoXP 的人工检查正好暴露了需要负责的环节。

OpenAI 重建 Git 服务端，以应对 Codex 带来的并发开发
OpenAI 称，新的 Git 兼容后端 Pando 已支撑其整个主代码库，推送延迟中位数下降近 80%，每日传输数据接近一 PB。此前分支、推送和 CI 读取增长，让旧系统可靠性一度低于 90%。Pando 让不同分支独立更新，并重复使用可缓存的数据包，代价是不再保证跨分支读取对应同一时点。文章还介绍用 Agent 持续测试，并以 Lean 和 TLA+ 检查系统性质；性能数字为 OpenAI 自报。
🦐点评：Pando 解决的是 Codex 放大提交量后暴露的基础设施成本。开发工具投资可以沿着推送、CI、评估和审阅的费用增长找需求，但要问客户是否已经碰到预算或可靠性上限；仅为 OpenAI 这种极端规模设计的能力，未必有足够大的付费市场。

Broccoli AI 从水管店接线做起，两轮融资合计5,200 万美元
Broccoli AI 的产品从预约提醒扩展到接听电话、查询师傅排班、跟进报价与客服质检，直接写入 ServiceTitan 的调度系统。据这篇编译，A、B 轮合计融资5,200 万美元，约3 亿美元估值来自媒体知情人士。创始人此前走访140 家承包商，随后在 Armstrong Plumbing 店里工作三个月，先小范围上线，再逐步替换人工答录服务。公司预计年底年化收入超过6,000 万美元，仍属预测；文中超过10 亿美元的年化预约订单额是客户业务金额，不能算成 Broccoli 的收入。
🦐点评：Broccoli 先卖风险较低的预约提醒，再进入漏接电话造成收入损失的场景，销售路径比“声音像真人”更有参考价值。不过公司称至少三成工程师仍驻客户现场，尽调要追踪新店部署工时是否下降，以及 ServiceTitan 自己补齐语音功能后，客户为什么还续约。

红果收紧内容补贴，AI 漫剧承接更低成本的供给
晚点重发三月报道并补充最新导语：援引 QuestMobile，九月红果日活超过 2 亿、人均每日使用166 分钟，同时称年内收紧制作方保底补贴、计划年底取消观众金币奖励。三月正文记录每部20 万至 35 万元保底费退出后，一些真人短剧团队停拍并转向 AI 漫剧，当时的1.2 亿日活不能当作最新数字。制作、分发与分账都围绕平台数据调整，同一小说也能被不同团队反复改编。文中 AI 内容每分钟约 500 元的成本是报道案例口径，不能外推为所有项目的统一成本。
🦐点评：红果撤掉保底后仍扩大领先，说明制作降本未必能让承制公司留下更多利润。投 AI 漫剧团队，应看脱离补贴后的回款和版权归属；如果选题、流量与结算都由红果决定，工具提高的效率很可能先被平台和更低报价的同行拿走。

卡兹克分享个人 Agent 自动化：统一事件入口，发布交给独立 CI
作者把定时任务、用户反馈和告警统一为事件，由中台按规则分配给不同 Agent，本地 Mac 通过长轮询接单，并控制去重与并发。开发 Agent 提交代码后，由独立 CI 承担审查、测试、合并、发布和线上版本核实，只把需要判断的事项送到飞书卡片。作者自报两周四个项目审查298 个 PR，提出333 个问题、合并前修复306 个；审查轮数上限为三次。已作出的决定另行保存，避免反复询问；这些是个人系统经验与内部统计，未独立验证。
🦐点评：作者称每月300 美元模型订阅基本够用，提示单卖任务调度界面的价格空间可能很有限。作者专门把发布与线上核实交给 CI，反而说明企业客户可能愿意为可靠交付、权限管理和故障追溯付费；要验证的是减少了多少盯守时间，而非开了多少 Agent。
