软件 IP 的重估：复制与迁移成本下降，SaaS 的研发资产假设受到挑战
Martin Alderson 认为，Agent 同时降低软件开发、功能复制和客户迁移的成本，削弱了部分 SaaS 依赖的技术稀缺性。他判断，新增需求会更多流向细分定制软件，而销售和交付未必能像编程一样提速，因此软件数量增加不等于单家公司市场空间扩大。他进一步质疑，把高额研发支出视为长期资产、或为难以自建的技术支付并购溢价的逻辑，是否仍然成立。这是一套估值分析框架，文中没有给出软件行业已发生普遍减值的实证数据。
🦐点评：若 Alderson 对 Agent 降低迁移成本的判断成立，历史净收入留存率就不能直接代表未来定价权。看 SaaS 标的时，应拆开客户留下来的原因：数据授权、渠道与业务责任可能仍有价值，功能齐全和迁移麻烦则需要重新验证；并购退出也更可能按客户关系而非累计研发投入定价。
martinalderson.com
Monaco 买 Devin、自建 Agent 工作环境，AI 编程的约束转向审查与组织知识
Monaco 在评估代码审查工具后继续使用 Devin，却因运行、复现故障和测试需要适配自身云环境而自建 Agent 工作空间；内部 Hal 可调查故障并提交 PR，也能回答销售对产品的提问。Mihail Eric 因旧作业容易被 Agent 一次完成，将 Stanford CS146S 的部分作业改为开源贡献，由真实维护者审核。文章转引 Faros 研究称，高 AI 采用团队合并的 PR 数量多 98%，但 PR 审查时间长 91%。访谈还提出，Agent 除了读取当前代码，也需要知道团队为何曾否决某项修改。
🦐点评：Monaco 对 Devin 与工作环境作出不同采购选择，说明“每家公司都要用”不等于“每家公司都会外购”。开发工具创业者更需要证明，自己能跨团队积累审查反馈和历史决策，并降低客户持续维护成本；只把模型接进 PR 流程，容易在客户熟悉用法后被内部实现替代。
latent.space
LLM 会把 AI 系统设计带入错误路线，生成代码能力与架构判断仍有落差
Sean Goedecke 举出一个记忆矛盾检测案例：Agent 没有直接调用 LLM 判断，而是长期搭建无法完整处理自然语言含义的符号求解系统。他开发 Autodeck 时，也见过 Agent 用正则和关键词硬做适合模型判断的分类任务。作者提出训练代码偏旧、强化学习环境缺少模型 API，以及一般软件设计能力不足等可能解释，但明确没有证实训练机制的影响。他的结论是，能实现复杂程序，并不意味着模型会选对解决问题的方法。
🦐点评：Autodeck 的例子提醒我们，AI 开发产品若只演示写代码速度，会漏掉最昂贵的失败：在错误架构上持续投入。能尽早识别不可行方案、提出替代设计并用业务样本比较效果的产品，才有机会从按 token 收费走向按减少返工收费；演示时应让 founder 展示一次方向纠错。
seangoedecke.com

Computer Use 对谈：可靠性、审批与遗留软件接入决定企业能用到哪一步
Z Potentials 编译 a16z 对 OpenAI 产品负责人 Ari Weinstein 与 James Sun 的访谈，核心应用包括操作缺少 API 的旧软件、财务对账、采购及跨系统工作流。受访者用97%与99%的差别形容可靠性改善的重要性，这是体验类比，并非文中提供的实测成功率。团队介绍 Guardian 逐项检查操作、企业配置人工介入程度，以及 dots 主动发现遗漏邀请、提取 Sentry 日志等内部案例。他们认为下一阶段还需解决本地与云端浏览器状态割裂，并让移动端用户更容易获得云电脑能力；增长与能力描述均为团队自述。
🦐点评：Ari 和 James 谈到的旧财务软件没有便捷 API，给创业公司的切口很具体：谁能把账簿核对结果接到客户的审批、追责与后续处理，谁才接近掌握业务预算。通用 Computer Use 逐渐普及时，单次代点鼠标会更难收费；垂直公司的定价权要靠持续正确交付，以及出错后能定位、补救和承担服务责任。
